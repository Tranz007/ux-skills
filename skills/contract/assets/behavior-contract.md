# [Feature] behavioral contract

## Scope

State the user outcome and which part of the experience this contract covers.

## Behavior

### [Condition or transition]

```text
When <trigger or condition>
→ the system <behavior>
→ the user sees/hears/can do <outcome>
→ relevant state <persists/resets/changes>
→ recovery is <behavior>
```

Repeat for meaningful transitions only.

## Shared components and patterns

Reference authoritative system behavior rather than duplicating it.

## Accessibility behavior

Capture established focus, semantics, announcements, keyboard behavior, or other requirements that engineering and QA must preserve.

## Unresolved clauses

List behavior that cannot be specified yet without a product, UX, engineering, accessibility, or policy decision.

## Related artifacts

Link the approved design, handoff, decision records, tickets, and system documentation.
